# Cute Hermes Skills 管理者說明

給維護這個 repo、或處理 Google／學校帳號設定的人。

## 1. Google 端設定紀錄（全校共用，只做一次，已完成）

| 項目 | 設定 |
|------|------|
| Google Cloud 專案 | `hermes-gm`（組織 gm.cute.edu.tw，建立者 shein@gm.cute.edu.tw） |
| 啟用的 API | Gmail API、Google Drive API |
| OAuth 同意畫面 | App 名稱 hermes-gm，使用者類型 **Internal**（只有 gm.cute.edu.tw 帳號可授權，不需 Google 審核，refresh token 不會 7 天過期） |
| OAuth Client | `hermes-gm-desktop`，類型 **Desktop app** |
| 使用的權限（scope） | `gmail.modify`、`drive`（完整雲端硬碟權限） |
| Client ID／Secret | 內建在 `skills/gmail-oauth/scripts/gmail_oauth.py`（Desktop app 的 secret 依 Google 說明不視為機密；Internal 設定下外部帳號無法使用） |

其他使用者**不需要**進 Google Cloud Console，只要安裝 skill、第一次使用時按「允許」。

管理位置：
- 專案／API：<https://console.cloud.google.com/apis/dashboard?project=hermes-gm>
- OAuth Client：<https://console.cloud.google.com/auth/clients?project=hermes-gm>
- 若要重新產生 client secret：在 Clients 頁新增 secret，更新程式中的 `_DEFAULT_CLIENT_SECRET` 後推上 GitHub，各電腦重裝 skill。

### Google Workspace 管理控制台注意事項

- 若授權時出現「管理員已封鎖」：到 **安全性 → 存取權和資料控管 → API 控制項**，確認內部（網域擁有）的應用程式受信任，或把 hermes-gm 設為信任。
- 個別使用者在 <https://myaccount.google.com/permissions> 可以看到並移除 hermes-gm 的授權。

## 2. 每台電腦的授權紀錄

- 存在該 Windows 使用者的 `%USERPROFILE%\.config\gmail-oauth\`（WSL 為 `~/.config/gmail-oauth/`）：
  - `token.json`：gm 帳號、已授權功能、授權時間、授權時的 skill 版本（含 token，勿外流）
  - `auth-history.log`：每次授權一行紀錄
- 跟 agent 說「gm 授權狀態」可查看。
- 移除／重裝 skill 不會刪除這些檔案。

## 3. 修改 skill 的規則

1. 每個 skill 是 `skills/<名稱>/` 一個資料夾（Hermes tap 只掃 `skills/` 下一層）。
2. SKILL.md 呼叫程式一律寫成 `bash "${HERMES_SKILL_DIR}/scripts/..."`，**要加雙引號**（Windows 路徑有反斜線、可能有空格）。
3. **不可以**在 SKILL.md 或程式裡放 `curl ... | bash` 之類「下載後直接執行」，Hermes 安全掃描會判定為危險並擋下安裝（連 `--force` 都不行）。
4. `platforms:` 只能用 `windows`、`linux`、`macos`。Hermes 沒有 `wsl`；WSL 裡的 Hermes 算 `linux`。
5. 使用者資料（token、搜尋結果）要放在 skill 資料夾以外，因為更新時 skill 資料夾會被整個換掉。
6. 改完要更新 SKILL.md 的 `version:` 和 [CHANGELOG](../CHANGELOG.md)，推上 `main`，再請各電腦照使用說明第 1 節重裝。

### 新增 Google 權限（例如日曆）

在 `gmail_oauth.py`：

```python
FEATURES = {"gmail": GMAIL_SCOPE, "drive": DRIVE_SCOPE, "calendar": CALENDAR_SCOPE}
SCOPES = f"{GMAIL_SCOPE} {DRIVE_SCOPE} {CALENDAR_SCOPE}"
```

新指令裡呼叫 `get_access_token("calendar")`，並在 hermes-gm 專案啟用對應 API。
各電腦更新後，舊功能照常使用；第一次用到新功能時 agent 會收到 `REAUTH_REQUIRED` 和授權網址，使用者按一次「允許」即可，不需要解除綁定。

## 4. 推送前自我檢查

用 Hermes 原始碼內的掃描器確認兩個 skill 都是 `safe`：

```bash
python -c "import sys; sys.path.insert(0,'<hermes-agent 原始碼路徑>'); from pathlib import Path; from tools.skills_guard import scan_skill; [print(s, scan_skill(Path('skills/'+s), source='github').verdict) for s in ('outlook-com','gmail-oauth')]"
```

推上後在任一台電腦執行 `hermes skills update`（或照使用說明重裝），`hermes skills list` 看到新版本號即完成。
